# Диагностика парсеров FunPay / Lolzteam

У FunPay нет официального API — программа читает обычные HTML-страницы сайта и разбирает их по CSS-селекторам
(`a.tc-item`, `.tc-price`, `.media-user-name` и т. д.). Когда FunPay меняет вёрстку, какая-то функция перестаёт
работать: пустой список лотов, «не удалось определить цену», не создаётся лот, не видны чаты.
Диагностика за одну минуту проверяет все парсеры на **ваших реальных страницах** и собирает обезличенный отчёт,
по которому разработчик быстро поправит селекторы.

## Когда запускать

* После обновления программы или если что-то перестало работать (поиск ничего не находит, лоты не публикуются,
  продажи/чаты не загружаются, «проверка подключения» проходит, а функции — нет).
* По просьбе разработчика, когда вы сообщаете об ошибке.

## Как запустить

**Из командной строки** (Windows — двойной щелчок не подойдёт, нужен параметр):

```
run.bat --diagnose
```

или `./run.sh --diagnose` (macOS / Linux), или `python -m app --diagnose`. Программа не запускает веб-интерфейс,
а последовательно выполняет проверки (с паузами между запросами, как настроено в `request_delay`), печатает
сводку на русском и завершается. Код выхода `0` — всё в порядке, `2` — есть ошибки.

**Из работающего приложения** (HTTP API; кнопка в интерфейсе появится позже):

* `GET http://127.0.0.1:8787/api/diagnostics/run?funpay=1&lolz=1` — выполнить проверки и вернуть отчёт (JSON).
  Параметры: `funpay=0` / `lolz=0` — пропустить источник, `subcategory_id=148` — какую подкатегорию FunPay
  использовать как образец (по умолчанию — первая «Аккаунты» первой игры, где она есть).
* `GET http://127.0.0.1:8787/api/diagnostics/report` — последний сохранённый отчёт.

## Что проверяется

FunPay (по порядку; если авторизация не прошла, остальные проверки FunPay пропускаются):

1. `funpay_login` — главная страница: имя пользователя, id, csrf-токен.
2. `funpay_categories` — список игр и подкатегорий; найдена ли игра World of Tanks.
3. `funpay_list_lots` — список предложений подкатегории-образца: сколько лотов, у скольких есть цена, продавец, заголовок.
4. `funpay_list_filters` — фильтры этой подкатегории (сервер, сторона и т. п.).
5. `funpay_get_listing` — страница первого лота из списка: заголовок, цена, продавец, названия атрибутов.
6. `funpay_lot_form` — форма создания лота: имена полей, наличие обязательных (`csrf_token`, `node_id`,
   `fields[summary][ru]`, `price`).
7. `funpay_my_lots` — наши предложения в подкатегории (только количество).
8. `funpay_sales` — страница продаж (только количество по статусам).
9. `funpay_chats` — список чатов (только количество и число непрочитанных).

Lolzteam (через официальное API): `lolz_me` (токен), `lolz_categories`, `lolz_params` (фильтры одной категории),
`lolz_search` (одна страница поиска — только количество и имена полей).

Каждая проверка в отчёте: `ok` (`true` / `false` / `null` — пропущена), `details`, `elapsed_ms`, `hint`
(что делать: обновить `golden_key`, какой селектор перестал находиться), `selectors` (сколько элементов находит
каждый ключевой селектор на странице — `0` означает, что именно он сломался) и `snapshot` (имя файла со снимком).

## Что сохраняется и где

Папка **`data/diagnostics/`** рядом с программой:

* `report.json` — отчёт: время, версия программы, версия Python и ОС, сводка настроек (**только флаги**
  «задан / не задан» для `golden_key`, токена, прокси, User-Agent — без значений), результаты проверок.
* `funpay_<проверка>.html` — обезличенные снимки страниц FunPay (не более 400 КБ каждый), по которым разработчик
  видит реальную вёрстку. Для формы лота сохраняется HTML формы, для Lolzteam — `lolz_*.json` с именами полей.

Отправьте разработчику всю папку (можно заархивировать). Она создаётся заново при каждом запуске диагностики.

## Что НЕ собирается (приватность)

Перед сохранением каждая страница обезличивается — заменяются на `***`:

* cookie `golden_key` и `PHPSESSID`, токен Lolzteam, csrf-токен (атрибут `data-app-data`, скрытые поля формы);
* ваш id пользователя и id других пользователей в ссылках `/users/N/`;
* ваше имя (`.user-link-name`), имена продавцов и покупателей (`.media-user-name`), балансы;
* тексты сообщений чата, адреса e-mail и похожие на телефон числа.

В отчёт `report.json` попадают **только количества и названия полей**: ни имён покупателей, ни текстов сообщений,
ни значений полей формы, ни баланса. Названия лотов и цены в снимках списка остаются — это публичная информация
на сайте, без неё нельзя проверить разбор цен.

Диагностика не создаёт, не меняет и не удаляет лоты, не отправляет сообщения — только читает страницы.
