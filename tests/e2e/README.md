# E2E-тесты веб-интерфейса

Сквозные тесты запускают **настоящее приложение** (`create_app` + uvicorn в фоновом потоке на
свободном порту) и кликают по интерфейсу в **headless Chromium** через Playwright.
Внешние площадки заменены фейковыми источниками (те же данные, что в `tests/test_api.py`):
в сеть тесты не ходят. База данных и профили каждого теста лежат во временной папке,
`config/settings.yaml` не трогается.

## Запуск

```bash
. .venv/bin/activate
pytest tests/e2e -q
```

Тесты входят в общий прогон `pytest -q` (папка `tests/`). Весь набор e2e занимает
около 15 секунд (запуск Chromium ~1 с, далее 1–3 с на сценарий).

### Что нужно

- `playwright` для Python (`pip install playwright`);
- бинарник Chromium. Ищется по маскам
  `/opt/pw-browsers/chromium-*/chrome-linux/chrome` и
  `~/.cache/ms-playwright/chromium-*/chrome-linux/chrome`; другой путь можно указать
  переменной окружения `E2E_CHROMIUM=/путь/к/chrome`.

Если Playwright не установлен или браузер не найден (например, в CI без браузеров),
e2e-тесты **пропускаются** целиком, остальной набор остаётся зелёным.

### Отладка

- `E2E_HEADED=1 pytest tests/e2e -q -k found` — запуск с окном браузера и замедлением
  действий (удобно смотреть, что происходит).
- При падении теста полный скриншот страницы сохраняется во временную папку теста,
  а текст области `#main` и ошибки консоли печатаются в выводе pytest
  (раздел «Captured stdout teardown»).
- Не запускайте несколько сессий pytest параллельно с общим `--basetemp`: временные папки
  приложения могут быть удалены другой сессией.
- По окончании каждого успешного теста проверяется, что в консоли браузера не было
  ошибок (`console.error`) и необработанных исключений. Ожидаемые ответы API 400/409
  (валидация) игнорируются.

## Сценарии (`test_ui.py`)

| Тест | Что проверяет |
|------|---------------|
| `test_dashboard_search_run` | Панель: бренд в боковой панели, кнопка «Найти аккаунты», таблица «Последний поиск» (получено 4 объявления), плитка кандидатов |
| `test_found_page_filters_and_actions` | «Найдено»: 2 кандидата, чипы статусов показывают отклонённые (2), текстовый фильтр, «Проверить», «Скрыть» → «Скрыто» |
| `test_preview_modal_draft_and_publish` | Предпросмотр лота: заголовок и цена 29 000, правка цены → черновик 31 000 ₽ на странице «Лоты», «Опубликовать» → лот активен, фейковый FunPay получил цену 31000 |
| `test_lots_check_source_activate_delete` | «Лоты»: «Проверить исходник» при недоступном исходнике снимает лот и показывает «недоступен», «Активировать», «Удалить» с подтверждением |
| `test_profile_editor_criteria_and_tester` | Профили: карточка, редактор, вкладка «Критерии», добавление тега must_any, сохранение, тестер критериев |
| `test_settings_save_and_auth_check` | Настройки: сохранение паузы 2.5 с, пустое поле golden_key не затирает ключ, «Проверить подключение» |
| `test_log_page_shows_search_events` | Журнал: события поиска («поиск завершён»), фильтры по типу и уровню |

## Устройство (`conftest.py`)

- `browser` (сессия) — один Chromium на весь прогон, запускается через `executable_path`.
- `e2e_app` (на тест) — `Settings` с тестовыми ключами, `ProfileStore` и `Storage` во
  временной папке, фейковые `FunPay`/`Lolz`, `create_app(ctx, start_monitor=False)`,
  uvicorn в потоке. Даёт `base_url`, `api` (httpx-клиент для подготовки данных и проверок),
  `funpay.created`/`active_calls` (что ушло бы на FunPay), `run_search()`.
- `page` (на тест) — новый контекст и вкладка; собирает ошибки консоли и исключения страницы.
